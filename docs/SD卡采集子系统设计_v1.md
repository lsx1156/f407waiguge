# SD 卡数据采集子系统 · 设计（v1 · 待批准）

> 状态：**设计草案，未动任何固件代码。**
> 目标：把 1 kHz 关节数据**直接落 SD 卡**，使采集脱离 PC 可独立进行（与「F407 离线版」定位一致）。

---

## 〇、v1.1 修订（2026-09-12，用户已定）

**决策：放弃按键；上电即在 ZERO（零阻力）模式下连续采集，直至断电。**

由此产生的**强制配套**：

| 项 | 要求 | 原因 |
|---|---|---|
| **周期 `f_sync()`** | 每 **≤2 s** 同步一次（或每 128 KB，取先到者） | **断电就是唯一的"停止"**。不同步则 FAT 链与目录项未落盘 → 断电后文件 0 字节或不存在 |
| **ZERO 模式硬禁** | 采集固件**编译期禁用** GAIT/ARM_ASSIST/INDUSTRIAL | 全程无人干预，不能有任何助力路径被激活 |
| 文件命名 | 上电扫描卡内 `LOG_*.BIN` 取最大号 +1 | 无按键 → 每次上电 = 一个新文件 |
| 会话时长 | 无固定上限，随断电结束 | 112 kB/s = 6.7 MB/min；32 GB 卡约 80 h |
| 元数据 | 先不做 `META.TXT`（最快版） | 无输入界面，实验记录先记纸面 |
| 头部记录数 | 每 2 s 与 `f_sync` 一起回写一次 | 断电后能精确知道有效记录数 |

**接口改动极小**：ISR 内 `report_frame_build()` 之后加一行 `sdlog_push(&frame)`（纯内存拷贝，µs 级）；SD 写入全在主循环。

## 1. 可行性核查（已实测，非推测）

| 项 | 结论 | 证据 |
|---|---|---|
| SDIO 引脚冲突 | **无冲突** | SDIO 固定 PC8/9/10/11(D0-D3)、PC12(CLK)、PD2(CMD)；全工程 GPIO 解析显示这 6 个脚**均空闲**。已占用：GPIOC 1/4/5（ETH RMII）、GPIOD 0/1/3/4/5/8~15（FSMC + ETH_RESET PD3） |
| 缓冲内存 | **充足** | 外部 SRAM 1 MB @ `0x68000000`；`bsp_config.h` 内存图：`MEM_LOG`(64 KB) **已定义但全工程无人引用**；另有 **~656 KB 空闲区**（0x6805_C000~0x680F_FFFF） |
| 驱动 | 需加入编译 | 仓库有 `stm32f4xx_hal_sd.c`，但 `.uvprojx` 目前只编 `stm32f4xx_hal_sram.c` |
| 可复用代码 | **有** | 厂商例程 `实验39 FATFS实验`（同板）：`Drivers/BSP/SDIO/sdio_sdcard.c|h`（含 `HAL_SD_MspInit` 六脚 AF12 配置）、`Middlewares/FATFS/{source,exfuns}`（FatFS + diskio） |
| 启停/指示 | 已有 | `key_init()`/`key_scan()`（PE4=KEY0、PA0=WK_UP）、LED |

**SDIO MSP（照搬厂商，已核对无冲突）**：6 脚 `GPIO_MODE_AF_PP` + `GPIO_PULLUP` + `GPIO_SPEED_FREQ_HIGH` + `GPIO_AF12_SDIO`，使能 `__HAL_RCC_SDIO_CLK_ENABLE()`。

## 2. 架构

```
1kHz TIM6 ISR ──(112B ReportFrame)──┬─→ 上报 FIFO(128帧) → LwIP UDP → PC   [保留, 现场监视]
                                    └─→ SRAM 日志环形缓冲(大)              [新增]
                                              ↓ 主循环搬块
                                        FatFS f_write(SDIO, 512B 整数倍)
                                              ↓
                                        SD卡: LOG_xxxx.BIN
```

**要点**
1. **记录格式 = 现有 112 B `ReportFrame_t`**——SD 日志与 UDP 流**同格式**，PC 侧一套解析即可（`tools/collect_motion_data.py` 的解析逻辑直接复用）。
2. ISR 只做内存拷贝（µs 级），**绝不碰 SD**；SD 写入全在主循环。
3. 环形缓冲放**外部 SRAM**：取 **512 KB**（0x68060000 起，落在空闲区），1 kHz × 112 B = 112 kB/s → **≈4.6 s 缓冲**，足以吸收 SD 卡的写延迟尖峰（典型 10~250 ms）。

## 3. 文件格式

```
LOG_0001.BIN
├─ [0x0000] 文件头 512 B
│    magic "F407LOG1" | 版本 | 记录长度(112) | 采样率(1000) | 上电计数 |
│    板载时间戳起止 | 固件commit | 采集会话元数据(见 §5) | 保留
├─ [0x0200] N × 112 B 记录 (按 1 kHz 顺序, 与 UDP 流完全一致)
└─ 文件尾 512 B:  magic "F407END1" | 记录数 | 结束时间戳 | CRC32(全记录区)
```

- 写入按 **512 B 整数倍**（FatFS 扇区对齐），最小化擦写开销。
- 掉电时尾部丢失 ≤ 一个缓冲块（≤ 数十 ms 数据），**文件头已含起始信息，可解析已有部分**。

## 4. 控制方式（v1.1：无按键，全自动）

| 时点 | 行为 |
|---|---|
| 上电 | 挂载 SD（**卡需上电前插入**）；扫描 `LOG_*.BIN` 取最大号+1 建新文件；**立即开始采集** |
| 运行中 | 全程 ZERO 模式（其余模式编译期禁用）；每 ≤2 s `f_sync()` + 回写头部记录数 |
| **断电** | 即采集结束。已同步部分完整可读；最多丢最后 ≤2 s |
| 挂载失败 | LED/串口报错，系统照常运行（**不采集、不助力**） |

## 5. 元数据（解决"板子上没法输入受试者/负载信息"）

**做法**：实验者在 PC 上编辑卡内 `META.TXT`（键值对），固件上电时读取并**原样写入文件头**：

```
SUBJECT=S1
SUBJECT_MASS=75
LOAD_KG=0
LOAD_POS=右手 r=0.35m
MOUNT=站立位 臂自然下垂
THETA0_DEG=-12.5
OPERATOR=ZS
NOTE=G0 baseline
```

读不到该文件也能采集（元数据留空并在串口提示）。

## 6. 主要风险与对策

| 风险 | 对策 |
|---|---|
| SD 卡兼容性（时钟/上拉） | 初始化 400 kHz → 工作 ≤24 MHz；先用厂商例程验证，再逐级提速 |
| 写延迟尖峰（内部擦除，可达数百 ms） | 512 KB SRAM 环形缓冲（4.6 s 余量）；写失败记 `drop_cnt` 并写入尾部 |
| 掉电丢数据 | 头/尾魔数 + 记录数 + CRC32；按 4.6 s 块周期 `f_sync` 落目录项 |
| 看门狗（IWDG）被长写饿死 | 写前/写后 `HAL_IWDG_Refresh`；分块写，单次 ≤64 KB |
| 采集期间误触其它模式 | 采集固件仍为 ZERO 专用（方案 §2 模式硬禁） |

| # | 决策 | 结论 |
|---|---|---|
