## 一、缺陷清单

### H1 【高】1 kHz 控制 ISR 内 printf 阻塞 ≈ **43 ms/秒**

**证据链（三处代码互证）**

| 环节 | 位置 | 内容 |
|---|---|---|
| 宿主 | `App/control/control_isr.c:708-714` | `HAL_TIM_PeriodElapsedCallback(TIM6)` → `control_isr_process()`；TIM6 = 84 MHz/84 → **1 kHz**，`NVIC 优先级 0`（最高） |
| 缺陷 | `App/control/control_isr.c:1000-1027` | **每秒 1 次、无条件**打印 1 + 6 = 7 行（`[ABO] mode=...` + 每关节 `J%d en=...`），≈ **495 字符** |
| 阻塞 | `User/main.c:76-81` | `__io_putchar()` = `while (!(USART1->SR & USART_SR_TXE)) {}` **逐字符忙等**；`main.c:234` 波特率 **115200** |

**量化**：495 字符 × 10 bit ÷ 115200 bps = **43.0 ms**

**后果**
- 每秒有 **43 ms** 控制中断被占住 → 该窗口内控制不执行（电机保持上一条指令）；
- 该窗口内**少生成 43 帧上报**；
- **关键特征：`seq` 仍然连续**（seq 只在生成帧时递增）→ 用"序列号缺口"判断丢包**完全看不出问题**；
- 实测（模拟复现）：`rate 958 Hz`、`coverage 95.69%`、`max_dt 44 ms`、`seq 丢帧 0`。

**对采集的影响**：方案 §10 要求丢包 <0.1%，实测 **4.3% 数据空洞** → **不达标，必须修**。

**修复建议**（最小改动，二选一）
1. 把这 28 行打印用 `#if 0` 关掉（或加宏 `ABO_DEBUG_PRINT`）：**推荐**，一行级改动；
2. 改为"置标志位 + 主循环打印"：ISR 只置 `g_abo_dbg_dump = 1`，`network_task_run()` 里打印。

### M1 【已更正 · 不成立】UDP 接收长度下溢 —— 我原先分析错了文件

**更正（2026-09-12）**：我最初把缺陷定位在 `Middlewares/lwip/arch/udp_net.c`，但**该文件是未被任何工程引用的残留副本**（`grep` 所有 `.uvprojx` 只列 `..\..\Middlewares\arch\udp_net.c`）。

**实际编译的 `Middlewares/arch/udp_net.c` 本来就有完整长度校验**：

| 位置 | 已有校验 |
|---|---|
| `udp_process_pbuf()` 入口 | `if (p == NULL \|\| p->tot_len < 1) return;` + `data_len > 1500 → return`（上界，防栈/堆放大） |
| 拷贝方式 | `pbuf_alloc(PBUF_RAW, data_len)` + `pbuf_copy_partial`（**不是**固定 256B 栈缓冲） |
| `FRAME_TYPE_COMMAND` | `data_len >= sizeof(CommandFrame_t)` 才比较 CRC |
| `FRAME_TYPE_PARAM` | `data_len >= sizeof(FrameHeader_t) + 4` 才取 `buf + data_len - 2` |
| `FRAME_TYPE_HEARTBEAT` | `data_len >= sizeof(HeartbeatFrame_t)` 才判 ESTOP |
| `PARAM_CMD_WRITE_ABO` | `payload_len >= 7` 才取 7 字节载荷 |

→ **无下溢、无越界读**。这一条是我审查方法上的失误（读到了同名死代码副本），特此更正。

**降级为 L4（低）**：`Middlewares/lwip/arch/udp_net.c` 作为重复文件长期并存，**是隐患**——若有人把它加回工程，就会引入下溢越界读。已按同样规则加固（见修复记录 F2），建议后续直接删除该副本。

### M2 【中】上报 FIFO 深度 32 帧（32 ms）余量过薄，且丢帧不可观测

- `App/bsp/bsp_config.h:250`：`FIFO_REPORT_SIZE = 32` → 1 kHz 下仅 **32 ms** 缓冲。
- 主循环网络任务（`tasks.c:29-33`）一有停顿（LwIP/ARP/链路事件/其它 printf），`fifo_write` 静默返回 0 丢帧。
- 丢帧计数 `g_dbg_fifo_write_fail` 存在（`udp_protocol.c:154-163`），但其打印在 `tasks.c:39` 被 **`#if 0` 关闭** → **板上完全看不到丢帧**。
- 对采集的意义：**只能靠 PC 侧序列号缺口发现**（这正是采集器要做 seq/coverage 双判据的原因）。

**修复建议**：`FIFO_REPORT_SIZE` 提到 128~256（128×112 B = 14 KB，F407 有 192 KB RAM）；把 `g_dbg_fifo_write_fail` 纳入 1 秒一次的统计打印。

### L1 【低】`joint_log_dump_csv()` 无保护读环形缓冲
`App/control/joint_unit.c:705-722` 在主循环读取 ISR 写入的 `g_log_buf`，无 `sys_arch_protect()` → 可能读到跨帧撕裂数据。仅调试导出用，影响有限。

### L2 【低】CAN 收帧无 DLC 校验
`App/can_motor/can_motor.c:648/699` 未检查 `header.DLC`。`g_can1_rx_data[8]`/`g_can2_rx_data[8]` 声明为 8 字节且只访问 [0..7]，**不会越界**；但 DLC<8 时尾字节为上一帧残留值。已被 `p_raw != 0x0000/0xFFFF` 边界检查部分兜住。

### L3 【低】板上运行时缺失关键统计
除 M2 的 FIFO 丢帧计数外，`tasks.c:39` 的整段 `[DBG] isr=/wr=/sent=/eth_in=` 打印被 `#if 0` 关闭，导致 LwIP 收包失败、ETH 中断计数等在板上不可见 → 现场排障只能靠 PC 侧。
